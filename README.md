# REST API для сайта объявлений (Flask)

Проект реализует REST API (backend) для сайта объявлений на **Flask**.

Реализовано:
- Создание / получение / редактирование / удаление объявлений (TSK-1)
- Модель объявления содержит поля:
  - заголовок (`title`)
  - описание (`description`)
  - дата создания (`created_at`)
  - владелец (`owner`, берётся из таблицы пользователей)
- Дополнительно реализована система прав и авторизация(ADD-1):
  - Создавать объявление может только **авторизованный** пользователь
  - Редактировать/удалять объявление может только **владелец**
  - Таблица пользователей содержит поля: `id`, `email`, `password_hash`
  - Авторизация по **JWT** (Flask-JWT-Extended)

## Установка и запуск

### 1) Установка зависимостей

Создайте виртуальное окружение и установите зависимости:

```bash
pip install -r requirements.txt
```

### 2) Запуск сервера

Запуск:

```bash
python main.py
```

По умолчанию сервер будет доступен по адресу:

```
http://127.0.0.1:5000
```

## База данных

Используется SQLite:

- файл базы создаётся автоматически (например `ads.db`)
- таблицы создаются автоматически при старте приложения

Важно:
- при изменении схемы (например, переход от `owner` к `owner_id`) проще удалить файл `ads.db` и перезапустить сервер, чтобы таблицы создались заново.

## Основная сущность: Объявление

### Поля объявления

- `id` — идентификатор
- `title` — заголовок
- `description` — описание
- `created_at` — дата создания (человекочитаемый формат)
- `owner` — владелец (в дополнительном задании объект с `id` и `email`)

Пример ответа:

```json
{
  "id": 1,
  "title": "Продам ноутбук",
  "description": "Core i7, 16GB RAM, SSD 512GB",
  "created_at": "19.01.2026 10:40:11",
  "owner": {
    "id": 1,
    "email": "ivan@mail.com"
  }
}
```

## Авторизация и права доступа (дополнительное задание)

### Регистрация пользователя

`POST /auth/register`

Тело запроса:

```json
{
  "email": "ivan@mail.com",
  "password": "123456"
}
```

Ответ: `201 Created`

---

### Логин пользователя

`POST /auth/login`

Тело запроса:

```json
{
  "email": "ivan@mail.com",
  "password": "123456"
}
```

Ответ: `200 OK`

```json
{
  "access_token": "JWT_TOKEN"
}
```

---

### Использование токена

Для защищённых запросов передаётся заголовок:

```
Authorization: Bearer <JWT_TOKEN>
```

## API эндпоинты

### Публичные эндпоинты

#### Получить список объявлений

`GET /ads`

Ответ: `200 OK`

---

#### Получить объявление по id

`GET /ads/<id>`

Ответы:
- `200 OK` — объявление найдено
- `404 Not Found` — объявления нет

---

### Защищённые эндпоинты (требуют JWT)

#### Создать объявление

`POST /ads`

Требуется JWT.

Тело запроса:

```json
{
  "title": "Продам ноутбук",
  "description": "Core i7, 16GB RAM, SSD 512GB"
}
```

Ответы:
- `201 Created` — создано
- `401 Unauthorized` — нет/неверный токен
- `400 Bad Request` — ошибка валидации

---

#### Редактировать объявление (частично)

`PATCH /ads/<id>`

Требуется JWT. Разрешено менять только поля:
- `title`
- `description`

Тело запроса (пример):

```json
{
  "description": "Обновлённое описание"
}
```

Ответы:
- `200 OK` — обновлено
- `401 Unauthorized` — нет/неверный токен
- `403 Forbidden` — пользователь не владелец объявления
- `404 Not Found` — объявления нет
- `400 Bad Request` — ошибка валидации / неизвестные поля

---

#### Удалить объявление

`DELETE /ads/<id>`

Требуется JWT.

Ответы:
- `200 OK` — удалено
- `401 Unauthorized` — нет/неверный токен
- `403 Forbidden` — пользователь не владелец объявления
- `404 Not Found` — объявления нет

## Коды ошибок

API возвращает ошибки в JSON-формате:

```json
{
  "error": "Сообщение об ошибке"
}
```

Типовые коды:
- `400` — ошибка входных данных
- `401` — требуется авторизация / неверный токен
- `403` — нет прав (не владелец)
- `404` — объект не найден
- `409` — конфликт (например, email уже зарегистрирован)
- `500` — внутренняя ошибка сервера

## Тестирование через requests.http (VS Code REST Client)

В проекте можно использовать файл `requests.http`:
- с двумя пользователями (TSK-1)
- с успешными и провальными запросами (ADD-1)
- токен подхватывается автоматически после выполнения login-запросов (TSK-1)

Для работы установите расширение **REST Client** в VS Code, откройте `requests.http` и нажимайте **Send Request** над нужным запросом.

## Примечания по безопасности для дополнительного задания (ADD-1)

- Пароли хранятся в виде **хэша** (`password_hash`), исходный пароль не сохраняется
- Владелец объявления определяется по JWT (поле `owner_id`), клиент не может подменить владельца в запросе
